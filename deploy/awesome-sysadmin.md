# awesome-sysadmin listing (LazyBackup)

> **awesome-selfhosted is not an option.** Its `Backup` category is a redirect to
> awesome-sysadmin (`tags/backup.yml` → `redirect`), and its lint (`hecat`,
> `items_in_redirect_fatal = True`) fails any entry tagged `Backup`. Its PR
> template also rejects software that is already listed in awesome-sysadmin, so
> getting into one list permanently blocks the other.

## Where

Create **`software/lazybackup.yml`** (new file) in
[`awesome-foss/awesome-sysadmin-data`](https://github.com/awesome-foss/awesome-sysadmin-data),
branch `master`. The README of `awesome-foss/awesome-sysadmin` is generated by a
bot — never edit it by hand.

Rendered position: between **Duplicity** and **Minarca** (the exporter sorts by
filename, so `lazybackup.yml` lands there alphabetically).

```yaml
name: LazyBackup
website_url: https://lazy.zic.ar
source_code_url: https://github.com/Ceneka/lazybackup
description: Web UI for scheduled backups of filesystem paths, Docker volumes, database dumps, and Git mirrors between local disks, SSH servers, and S3-compatible storage, with encryption and restore.

  - MIT

  - Docker
  - Nodejs
tags:

```

Checked against their own rules and lint (`hecat`, `make awesome_lint` → passes):

- description is 187 chars (< 250), sentence case, ends with a dot;
- no redundant "self-hosted" / "free" / "open-source";
- ASCII only — `→` has no precedent in the 1,656 entries of both data repos;
- `MIT` exists in `licenses.yml`, `Docker` and `Nodejs` exist in `platforms/`;
- no `demo_url` (there is no interactive demo — the landing page is marketing);
- no `stargazers_count` / `updated_at` / `commit_history`: the metadata bot adds them.

The 12-month rule is the blocker: they count from the first tagged release, not
from repository creation (2025-03-07). Hold this file until **2027-08-13**, then
open the PR. Opening it earlier will most likely be closed with the canned reply.

## PR

1. Fork `awesome-foss/awesome-sysadmin-data`, branch `add-lazybackup`.
2. Add `software/lazybackup.yml` with the block above.
3. Commit `add LazyBackup`; PR against `master`, title `Add LazyBackup`.
4. Fill the PR template honestly: one item per PR, free software, not listed
   elsewhere, lint-clean, kebab-case filename, actively maintained, and the
   first-release checkbox only when it is actually true. Then answer the six
   questions in the template (why it is awesome, how long you have used it,
   personal vs professional setup, scale, pros/cons against alternatives,
   anything else). The template warns that a useless or biased answer gets the
   submission rejected.
5. CI runs `make install`, `make awesome_lint`, `make export_markdown`. A merge
   lands roughly a week after approval.

> AI policy: `awesome-selfhosted-data` explicitly forbids agents from opening
> issues/PRs or writing entry text that a person submits as their own. Submit
> this yourself, in your own words.
